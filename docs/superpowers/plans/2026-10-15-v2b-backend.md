# v2 B Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar o backend do questionário adaptativo (versão de protótipo): definição em `questionario.json`, endpoint para o aluno sem pesos, validação e gravação das respostas no caso, motor de triagem com pesos e alertas (vazios), e o bloco "questionário" no detalhe da coordenação.

**Architecture:** Um módulo novo `app/questionario.py` carrega e valida a definição, devolve a versão do aluno, valida as respostas recebidas, calcula os pontos e alertas e descreve as respostas para a coordenação. `casos.criar_caso` passa a gravar `respostas_json` e a chamar a triagem com os extras. As rotas ficam finas. O arquivo `app/questionario.json` é o conteúdo; uma cópia em `data_dir` o sobrescreve (mesmo padrão de `risk_terms.json`).

**Tech Stack:** Python 3.13, Flask, SQLite, pytest. Sem dependência nova.

**Spec:** `docs/superpowers/specs/2026-10-15-v2b-questionario-adaptativo-design.md`. Conteúdo de origem: `docs/v2b-questionario-bifurcacoes-rascunho.md` (rascunho do usuário, ainda não revisado).

## Global Constraints

- **Pesos e alertas nascem vazios** (`"pesos": {}`, `"alertas": []`); a triagem com respostas tem de dar o mesmo resultado da v2 A (teste de equivalência). Nunca preencher pesos ou alertas na definição entregue: são decisão do usuário.
- O aluno nunca recebe `pesos`, `alertas` nem `faixas`.
- Mensagens de erro da API em ASCII sem acento; entrada inválida = 400; caso inexistente = 404 `{"erro": "nao encontrado"}`. Texto livre continua só o relato.
- Textos do questionário sem travessão longo (— ou –); os textos das 25 opções das 5 situações aprovadas são **literais** (copiar de `frontend/src/aluno/situacoes.ts`, que veio de `DEFINICOES.md`).
- Nenhuma coluna guarda IP. Migração só com `ALTER TABLE ... ADD COLUMN` anulável, idempotente.
- Testes: nunca duas execuções do pytest ao mesmo tempo; usar `--basetemp` próprio; conferir o código de saída (sem `| tail` escondendo). Commits em português com `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; sem push. Subagentes: **sonnet ou haiku, nunca opus** (pedido do usuário).

## Review Focus

- `respostas` com JSON inválido, tipo errado, ids de outra situação, `unica` com dois valores, mais de 60 ids, mais de 8 KB, e `tipo` do formulário diferente do da situação: 400 e nada gravado (Task 2).
- Definição com id duplicado, referência a pergunta inexistente, `mostrar_se` apontando para resposta inexistente, peso ou alerta apontando para resposta inexistente, tipo inválido: a partida falha com mensagem clara (Task 1).
- Texto de opção ou pergunta no JSON que diverge do aprovado ou contém travessão longo (Task 1).
- Caso antigo (sem `respostas_json`) e caso cuja resposta aponta para id que sumiu da definição: detalhe não quebra (Task 4).
- Pedido sem `respostas` continua funcionando exatamente como hoje (Task 2).
